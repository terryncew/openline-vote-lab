The CLI exports are retained locally under ignored `artifacts/baseline/` and `artifacts/receiver/`; they contain public synthetic evidence only. They are regenerated by the documented command and are not bundled as fixed election records in the source release. Each run has fresh random keys, opaque ballot IDs, encryption randomness, and randomly assigned synthetic choices, so exact hashes differ.

`scripts/browser_smoke.py` reproduces the browser interaction checks against a **disposable** loopback server when Python Playwright and system Chromium are already installed. It rejects third-party page requests, resets the target election, and leaves a fresh receiver-mode experiment. It is optional, separate from the pinned core dependencies, and should never be pointed at a synthetic election whose state someone wants to keep. Its final run observed no page JavaScript errors or third-party requests. Screen-reader and human usability review remain unrun.

## What this evidence establishes

Within the supported fixed format, the implementation checks an authentic synthetic roster and election scope, one counted ballot per credential, voter and operator signatures, ElectionGuard ballot proofs, independently recomputed aggregation, both guardian decryption proofs, and the reported totals. It detects the selected adversarial records without assuming the operator's claimed totals are correct.

Public exports omit individual plaintexts and nonces. That is a conditional public-record confidentiality result, not protection against the local server: the server receives fake plaintexts and holds all role keys. Two guardians are simulated, not independently operated.

The archive-only limitation is a deliberate passing test of a **weaker claim**. An authentic witness checkpoint or retained receipt changes what an observer can detect. Such reference evidence cannot authenticate itself if obtained only from a dishonest operator after a rewrite. The actual simulator colocates its witness and operator; outside key custody and honest observation are modeled assumptions.

The optional receiver capability adds a scoped authorization check but gives the same outcomes as the baseline for the attack comparison. No new election encryption, tally-verification, completeness, or coercion guarantee is demonstrated. ElectionGuard, Helios, and Belenios already provide the relevant precedents. The experiment answers the research question without warranting a larger voting platform on novelty grounds.

## Unsafe and unproven properties

Compromised clients, coercion, vote buying, selective denial of service, malicious registration, key theft/collusion, witness equivocation, metadata leakage, and small-election disclosure remain unsolved. There is no cast-as-intended challenge procedure, real enrollment, secure key custody, verified erasure, recovery system, or production administration workflow.

The producer and verifier reuse the same cryptographic dependency. Internal adversarial review found and corrected serialization-type ambiguity, unsupported unproved metadata, predictable synthetic choice assignment, malformed API inputs, and artifact-read bounds. That is useful implementation review, **not an independent cryptographic audit** or a security certification.

Other operating systems, independent screen-reader/contrast assessment, distributed authority operation, and complete ElectionGuard specification conformance were not validated. This candidate intentionally supports a single fictional two-choice election format and the pinned reference implementation's older specification version. Dependency pins support repeatability, not a guarantee against supply-chain flaws or future vulnerabilities.

## Review and reproduce the candidate

Use the README commands for installation, tests, both simulations, and standalone verification. `scripts/build_release.py` packages explicit source/docs/test directories, omits generated election exports, private environment/cache/Git data, and normalizes archive timestamps. It produces a local deterministic source archive and checksum:

```sh
.venv/bin/python scripts/build_release.py
cd artifacts/release
sha256sum -c SHA256SUMS
```

The source archive is `openline-vote-lab-0.1.0rc1.tar.gz`. `SHA256SUMS` checks accidental changes to that local archive; it is not a signed release attestation.

Before considering further work, independent reviewers should inspect the supported proof coverage, signed-message and parsing boundaries, pinned sources/licenses, authentic anchor/checkpoint acquisition, role separation, privacy leakage, and usability. [RESEARCH.md](RESEARCH.md), [THREAT_MODEL.md](THREAT_MODEL.md), and [ARTIFACTS.md](ARTIFACTS.md) describe the claims and assumptions. Any deployment, public release, or public security claim requires explicit approval and additional review.
